title: "链路追踪"
---

Tracing（链路追踪）对智能体执行过程进行**全链路记录**，是企业级智能体应用实现可观测性的核心。它把一次请求的完整流程——用户输入、模型推理、工具调用、记忆与知识库读写、响应生成——转化为可分析、可追溯的结构化数据，为调试、监控和优化提供依据。

## 在 VeADK 中开启观测

为智能体配置一个 `OpentelemetryTracer`，并指定一个或多个 Exporter，即可开启全链路观测。下例使用 APMPlus Exporter：

<Tabs items={['代码', '所需环境变量']}>
  <Tab value="代码">
    ```python title="examples/tracing/tracing_exporter.py"
    import asyncio
    from veadk import Agent, Runner
    from veadk.tracing.telemetry.exporters.apmplus_exporter import APMPlusExporter
    from veadk.tracing.telemetry.opentelemetry_tracer import OpentelemetryTracer

    # 初始化 Tracing Exporter
    exporters = [APMPlusExporter()]
    tracer = OpentelemetryTracer(exporters=exporters)

    # 定义智能体并挂载 tracer
    agent = Agent(tracers=[tracer])

    runner = Runner(agent=agent)
    response = asyncio.run(runner.run(messages="hi!"))
    print(response)
    ```
  </Tab>
  <Tab value="所需环境变量">
    可通过环境变量配置 Exporter：

    - `OBSERVABILITY_OPENTELEMETRY_APMPLUS_API_KEY`：APM 服务的 API Key
    - `OBSERVABILITY_OPENTELEMETRY_APMPLUS_ENDPOINT`：APM 服务的 Endpoint，例如 `http://apmplus-cn-beijing.volces.com:4317`
    - `OBSERVABILITY_OPENTELEMETRY_APMPLUS_SERVICE_NAME`：APM 的 Service Name，例如 `python_coder_agent    - `OBSERVABILITY_OPENTELEMETRY_TRACE_CONTENT`：是否采集 Agent、LLM 与工具输入输出内容，默认 `true`

    或在 `config.yaml` 中定义：

    ```yaml title="config.yaml"
    observability:
      opentelemetry        trace_content: true
        apmplus:
          endpoint: ...
          api_key: ...
          service_name: ...
    ```
  </Tab>
</Tabs>

## 限制本地缓存

以下配置随本次修复提供，已发布的 1.1.14 及更早版本不支持这些配置

`OpentelemetryTracer` 默认保留最近的 1024 个 Span，估算数据总量最多为 16 MiB。达到任一上限时会淘汰最早的 Span；单个 Span 超过字节上限时不写入本地缓存，仍按原有配置交给云端 Exporter

在启动应用前，可通过以下环境变量调整本地缓存：

| 环境变量 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `OBSERVABILITY_OPENTELEMETRY_INMEMORY_ENABLED` | 布尔值 | `true` | 是否保留本地 Span 历史 |
| `OBSERVABILITY_OPENTELEMETRY_INMEMORY_MAX_SPANS` | 非负整数 | `1024` | 最多保留的 Span 数量，`0` 表示不保留 |
| `OBSERVABILITY_OPENTELEMETRY_INMEMORY_MAX_BYTES` | 非负整数 | `16777216` | 估算数据量上限，单位为字节，`0` 表示不保留 |

仅需云端观测时，在启动应用的终端设置：

```bash
export OBSERVABILITY_OPENTELEMETRY_INMEMORY_ENABLED=false
```

关闭本地缓存后，Span 标注、日志中的 Trace ID 和已配置的云端上报保持可用，`tracer.dump()` 写入空数组。启用缓存时，`dump()` 只包含仍保留的会话历史；用于关联会话的 Span 被淘汰后，对应链路也可能不再出现在本地导出中，完整历史应在云端观测平台查询

同一个 TracerProvider 下的 tracer 共享上述额度。配置在首次创建缓存时生效，修改后需重启应用或创建新的 Provider；字节数是缓存数据的估算值，不代表整个进程的内存上限

## Tracing 的价值

引入 Tracing 后，你可以：

- **调试与定位问题**：快速定位逻辑错误、工具调用失败或模型输出异常发生的环节；
- **性能分析**：通过各模块的执行耗时发现瓶颈，优化模型调用与工具执行策略；
- **审计与合规**：保留完整的请求、响应与决策记录；
- **多 Agent 协调**：分析多 Agent 协作中各 Agent 的调用关系与数据流向。

## Tracing 数据结构

Tracing 数据由一系列 **Span** 组成，每个 Span 记录一次操作（如调用模型、执行工具）的名称、ID、起止时间与属性。下面是单个工具调用 Span 的示例：

## 请求 Span 与流式 TTFT

VeADK 使用 OpenTelemetry Span 原生起止时间表达执行边界。VeADK AgentKit/Harness HTTP 应用在 ASGI 入口、请求体解析前创建 `http_request` server Span，在应用执行结束时关闭。直接执行 VeADK Runner 时创建 `runner_request` Span；在 HTTP 请求中调用 Runner 时复用该请求范围。上述边界不包含应用接收请求之前的客户端、网络和网关耗时。

每次 LiteLLM Chat 或 Ark Responses SDK 请求，在所属模型 Span 下创建 `model_request` client Span。其原生开始时间与 TTFT 计算使用的本地 SDK 请求起点相同，不代表服务端开始推理。VeADK 发起的重试/降级分别创建 Span；供应商/LiteLLM 内部不可观测的重试仍属于同一次 SDK 调用。

| 属性 | 类型 / 含义 |
| --- | --- |
| `gen_ai.span.kind` | SDK 请求 Span 上为 `llm`。 |
| `gen_ai.request.model` | 实际请求的模型。 |
| `gen_ai.request.stream` | 布尔值，表示实际 SDK 流式模式，不依赖 HTTP SSE 或 Runner 配置。 |
| `gen_ai.chat_completions.streaming_time_to_first_token` | 从 SDK 请求开始到首个生成增量到达的浮点秒数。 |

首个非空文本、推理或工具调用增量触发一次 TTFT 记录。元数据、空增量、usage、心跳和仅完成时返回的聚合内容不计入。非流式、无输出或未埋点路径省略 TTFT；SDK 模式未知时不从 Runner 配置推导。一个 chunk 可含多个 token，因此这是 SDK 侧观测耗时，不是供应商侧逐 token 时间戳。

同一个值通过现有全局 MeterProvider，在 `gen_ai.chat_completions.streaming_time_to_first_token` Histogram 记录一次，单位为 `s`。维度为 `gen_ai.request.model` 和 `gen_ai.operation.name=chat`。指标不依赖 token usage 或 Trace 采样；导出需要配置指标链路。负时钟间隔省略并产生诊断；真正测得的零值有效。

失败模型请求设置原生 Span Status 为 `ERROR`，`error.type` 为 `llm_error`、`timeout` 或 `cancelled`。请求 Span 使用 `request_error`、`timeout` 或 `cancelled`；HTTP 5xx 响应使用 `http_error`。主动关闭生成器不算错误。已观测的 TTFT 在中断后保留，本埋点不添加异常正文。

本埋点不再导出自定义 `veadk.request.*`、`veadk.model.*` 属性或自定义首 Token 事件。开始时间和首输出值仅作为内部计算状态。此变更替代此前自定义计时字段，不保留兼容别名。客户端渲染计时和 TPOT Histogram 上报不在本功能范围内。
