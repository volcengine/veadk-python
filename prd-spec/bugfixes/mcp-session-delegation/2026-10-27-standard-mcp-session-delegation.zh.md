# 普通 MCP 会话委托避免重复加锁

[English](2026-10-27-standard-mcp-session-delegation.md)

- 变更 ID：`mcp-session-delegation`；创建／修订：2026-10-27。
- 状态：测试分支已实现并验证；尚未发布。
- 组件：[MCP 会话分派](../../../specs/mcp-session-dispatch/README.zh.md)。

## 证据与范围

`TrustedMcpSessionManager.create_session` 持有 `_session_lock` 后，将普通连接委托给同样获取该不可重入锁的 `MCPSessionManager.create_session`。已授权的隔离探测在工具发现前停住。另一次 0.3 秒的离线复现，在受保护的传输工厂调用前超时；取消后锁已释放。这是本地分派缺陷，不能据此认定 MCP 凭据被拒绝。

`TrustedMcpToolset` 还会记录完整连接参数，其中可能包含鉴权头。初始化日志应标明传输类型，不得复现请求头或可能携带凭据的 URL。

目标：恢复普通 MCP 工具发现／调用，并安全记录初始化日志。非目标：修改厂商 TrustedMCP 鉴权、升级依赖、新建云资源、修改共享角色／路由，或认定 Sandbox 执行分段已验收。

## 需求与设计

- `FR-1`：普通 Streamable HTTP、SSE、stdio 在获取自定义 TrustedMCP 锁前委托父类；普通会话池、原生缓存元数据、并发和清理由父类负责。
- `FR-2`：仅 Streamable HTTP 且合并后的标记严格为 `x-trusted-mcp=true` 时使用现有自定义 TrustedMCP 分支；保留鉴权头、调用方字典和既有厂商选择规则。
- `FR-3`：初始化日志仅包含传输类名，不记录连接对象、请求头、密钥或完整 URL。
- `FR-4`：父类异常和取消继续传播，锁可继续使用；普通并发调用沿用父类会话池契约。

选择在自定义锁外判断模式并直接委托普通调用。改用可重入锁或新建无池化传输会掩盖所有权问题，并改变资源行为。公共签名、配置键、依赖范围和凭据来源均不变。配套组件规范记录拟实施的锁所有权和脱敏保证。

## 风险、授权与评审

- 厂商 TrustedMCP 路径保持不变；既有 mock 测试不能证明真实厂商鉴权兼容，这不属于本缺陷范围。
- 传输成功不证明上游 Trace 已传递。真实验证分别报告鉴权、返回值和关联结果。
- 凭据仅保存在内存并发送到已授权接收端；探测日志仅在内存中捕获，证据不保存原始日志、响应、Token 或 Prompt。
- 授权来自用户当前要求实施、核验一期开口且不扩权的目标；不新增权限、目标或资源。这里记录既有任务范围，不声称用户另外审阅了本文。
- 直接设计评审（未提供 `review-spec` 技能）：已核对锁所有权、精确标记语义、取消、公共 API／依赖不变、安全日志、可测试性和双语等价；范围内无实施阻塞。
- 实施前验证：离线复现为 `pass`（已复现缺陷）；新回归／门禁／真实重试为 `not_run`。实施后按实际结果同时更新双语记录。

## 兼容性复审补充

有界真实重试已进入原生会话创建，但发现另一处本地适配缺陷：Google ADK 2.7.1 调用 `_create_client` 时传入 `mtls_transport`、`session_key`，覆写方法却只接受请求头。扩展私有覆写方法，将普通连接的位置参数和关键字传输参数原样交给父类，不自行实现或替换鉴权及传输行为。先补充参数对象与请求头保持不变的失败回归，再实现修复。此项属于 FR-1/4 和 CON-1/3；直接复审确认不新增公开 API、依赖或权限。
