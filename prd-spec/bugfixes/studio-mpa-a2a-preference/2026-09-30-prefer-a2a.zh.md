## 证据、范围与需求

Studio 当前先探测 ADK `/list-apps`，仅在 404 后发现 A2A。
设置 `DISABLE_JWT_AUTH=true` 后 MPA 广告 ADK，原生会话创建先查询 `profile-status`，
其独立 RuntimePrincipal 鉴权在未配置 AgentKit 模式时仍要求公钥。该源码链解释
用户报告的缺公钥错误；尚未捕获具体失败的云端 URL。用户批准 MPA 优先 A2A，
同时保留当前鉴权开关。

- `FR-1`：已授权 MPA Runtime 提供有效 Agent Card 时，GET 代理 `list-apps`
  在探测 ADK 前返回 `["a2a-default"]`，即使 ADK 同时可用。
- `FR-2`：普通 Runtime 保持 ADK 优先及既有 404 A2A 回退。MPA 没有可用
  卡片时继续既有发现/错误流程。
- `FR-3`：选中 A2A 后会话使用原有创建/运行/历史映射，跳过原生 Profile/
  执行配置前置查询；鉴权、TOS、下载和 API Key 不变。不迁移已有原生会话。

## 设计、审查与边界

在 `_runtime_proxy` 完成 Runtime 授权、凭据解析和可信身份 header 构造后，
增加限定条件。复用有超时的 `_runtime_a2a_agent_card` 及 `a2a-default` 适配。
不增加 helper、配置、依赖或 UI，不修改 Runtime/Worker。只改变 GET `list-apps`，
其他方法/路径不变。既有 helper 失败返回无卡片，上游/客户端继续在 `finally`
清理，不捕获取消。类别来自可信控制面元数据而非浏览器；卡片 URL 归一化不变。

直接审查（`review-spec` 不可用）确认范围、可信授权、回退/资源处理、可测试性及
双语一致性。用户“改吧”批准前述方案。Ponytail 复用既有共享入口。视觉技能不适用：
不修改 UI、布局、样式或交互代码。

## 风险与上线

在 Studio 重新连接 MPA，刷新已缓存的发现应用。保存的原生会话不会自动改变，
A2A 历史沿用原有恢复/持久化限制。原生专属 Profile/配置功能不属于 A2A。
不保证修复卡片缺失或无关管理接口鉴权。回退时撤销新增条件即可恢复 ADK 优先。
实现测试不需要云资源、真实凭据或真实 Agent 执行。
