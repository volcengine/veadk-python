# Prefer the existing A2A bridge for MPA discovery

[中文版](2026-09-30-prefer-a2a.zh.md)

- Status: implemented; contract: [Runtime diagnostics](../../../specs/studio-runtime-diagnostics/README.md), `CON-13`

## Evidence, scope and requirements

Studio currently probes ADK `/list-apps` first and only discovers A2A on 404.
With `DISABLE_JWT_AUTH=true`, MPA advertises ADK, and native session creation
first requests `profile-status`, whose independent RuntimePrincipal gate still
requires a public key unless AgentKit mode is configured. This source chain
explains the reported missing-key error; the failing cloud URL is not captured.
The user approved preferring A2A for MPA while preserving this auth setting.

- `FR-1`: Given an authorized MPA Runtime with a valid Agent Card, GET proxy
  `list-apps` returns `["a2a-default"]` before probing ADK, even if ADK is available.
- `FR-2`: General Runtimes keep ADK-first discovery and existing 404 A2A fallback.
  MPA without a usable card continues the existing discovery/error path.
- `FR-3`: Selected A2A sessions use existing create/run/history mapping and skip
  native Profile/execution-config preflight; auth, TOS, downloads and API keys
  are unchanged. Existing native sessions are not migrated.

## Design, review and boundaries

Add a scoped guard after Runtime authorization, credential resolution and
trusted-user header construction in `_runtime_proxy`. Reuse the bounded
`_runtime_a2a_agent_card` helper and `a2a-default` adapter. No new helper,
configuration, dependency, UI or Runtime/Worker change. GET `list-apps` is the
only changed request; other methods/paths retain their existing behavior.
Existing helper failures return no card and its upstream/client cleanup remains
in `finally`; cancellation is not caught. Category is from trusted control-plane
metadata, not browser input. Agent Card URL normalization is unchanged.

Direct review (`review-spec` unavailable) confirms scope, trusted authorization,
fallback/resource behavior, testability and bilingual equivalence. User's
“改吧” approves the preceding plan. Ponytail reuses the existing shared entrypoint.
Visual skills are not applicable: no UI, layout, style or interaction code changes.

## Risks and rollout

Reconnect the MPA in Studio to refresh its cached discovered apps. Existing
saved native sessions do not change automatically, and A2A bridge history has
its existing restoration/persistence limits. Native-only Profile/configuration
features remain outside A2A. No guarantee is made that missing Agent Cards or
unrelated authenticated management endpoints are fixed. Restore ADK-first
discovery by reverting this guard. No cloud resources, credentials or real
agent execution are needed for implementation tests.
