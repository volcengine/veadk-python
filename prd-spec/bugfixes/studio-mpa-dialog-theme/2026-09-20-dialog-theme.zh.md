## 证据与目标

生产入口加载了旧页面样式，却未加载组件库主题样式。构建 CSS 中没有 `--studio-text-primary` 和 `--studio-bg-elevated` 的定义。MpaCreateDialog 使用这些变量且没有回退值，而 ModalLayout 回退到深色背景，正文继承的近黑文字因此无法阅读。用户截图在浅色智能体页面复现了问题。

使用现有组件主题恢复标签、输入值、创建计划和错误信息的可读性。不改变资源创建 API、配置、任务状态、部署或资源分配。

## 需求与设计

- FR-1：在生产 Studio 入口渲染前加载现有主题与组件主题 CSS；不新建配色体系，不覆盖基础组件样式。
- FR-2：根节点未指定主题时初始化 `data-theme=light`，与已有页面一致；保留显式指定的浅色或深色主题。不修改持久化偏好或组件预览的默认主题。
- FR-3：弹窗、输入框、文本域和按钮使用一致配色；标签与正文对比度至少为 4.5:1。桌面及 390px 窗口下保留缺配置禁止提交、重试、关闭及键盘行为。

修改限定于 `frontend/src/main.tsx`、本双语记录、前端 README 简短说明和对应的 `veadk/webui` 构建产物。加载共享样式也可能修正其他组件库控件；检查其作用域选择器并保持旧页面背景不变。无公共 API、持久化、权限或组件契约变更：本次恢复已有文档约定的组件主题行为。不涉及后端测试或云操作。

## 任务与验收

- T-1 / AC-1：修改生产代码前记录变量缺失和浏览器对比度失败。
- T-2 / AC-2：加载两个现有样式表并初始化缺失的根主题；验证浅色、深色配色以及显式主题不被覆盖。
- T-3 / AC-3：运行 `npm --prefix frontend test`、`npm --prefix frontend run build` 和 `npm --prefix frontend run test:webui-assets`；以隔离的配置响应在真实浏览器中验证实际弹窗、错误信息、重试、键盘焦点和窄窗口。
- T-4 / AC-4：检查差异、保留无关工作区修改，并在双语记录中写明实际结果。本次不包含提交、镜像发布或部署。

直接设计评审：pass。现有组件样式维护按钮和文本域的浅色变体，因此仅加载基础主题变量仍不完整。根主题初始化必须先于渲染，不能覆盖显式主题。双语范围与标识一致。仓库引用的 frontend-design、ui-ux-pro-max 技能在仓库和已安装技能目录中均缺失，按仓库前端规范执行。兄弟仓库的 review-spec 技能属于另一套工作流，本次不套用。
