# 每轮评测只运行一次，而不是每个用例各运行一次

[English](2026-10-27-evaluator-model-calls.md)

- 创建/修订日期：2026-10-27

## 背景、目标与范围

`ADKEvaluator.evaluate()` 遍历评测用例，并对每个用例的每一轮调用 `generate_actual_outputs()`。该方法本身已经会在评测集的**所有**用例上运行智能体。因此评测 `C` 个用例、`R` 轮，会运行 `C x R x C` 次智能体，而不是 `C x R` 次。使用真实模型时，每次运行都是一次付费调用。

在 1.1.19 上实测，并通过阅读代码确认 `main`（`2301477`）上的循环没有变化：用会计数的脚本化模型，3 个用例 x 1 轮产生 9 次模型调用，3 x 2 产生 18 次，6 x 2 产生 72 次。27 个用例、2 轮会产生 1458 次调用，而不是 54 次。评分本身没有错误：每个用例仍读取自己的结果，所以缺陷是成本和耗时，而不是正确性。`veadk eval --evaluator adk` 命令使用该评测器，因此同样受影响。`DeepevalEvaluator` 未检查。

修复方式是每轮只运行一次智能体，并用这些轮次的结果给每个用例评分。不改变阈值、指标、结果与失败信息的结构、公开签名、评测集格式，也不改变 `DeepevalEvaluator`。

## 场景与需求

- FR-1：给定 `C` 个用例和 `num_runs = R`，`evaluate()` 恰好调用 `generate_actual_outputs()` `R` 次，因此智能体总共运行 `C x R` 次。
- FR-2：给定与之前相同的实际输出，每个用例在相同的调用上、按相同的轮次顺序评分，并返回与之前相同的结果和失败信息。
- FR-3：给定一个失败的用例，只有该用例被报告为失败，其他用例不受影响。
- FR-4：每一轮的实际值在该轮运行后立即转换为 ADK 调用对象，因为下一轮会原地覆盖它们。

## 设计与契约影响

把轮次循环提到用例循环之上。每轮运行后，把所有用例的实际值转换为 ADK `Invocation` 对象（沿用现有转换逻辑，移入 `_to_actual_invocation`），并按轮次保存。在用例循环内，该用例的实际调用就是每一轮中它自己的调用，按轮次顺序排列，与之前循环产生的结果一致。否决的方案：按调用序号缓存 `generate_actual_outputs()` 的结果，会与循环顺序耦合；让 `generate_actual_outputs()` 接收一个用例参数，会改变 `DeepevalEvaluator` 共用的 `BaseEvaluator` 契约。

公开导入、签名、默认值、返回值、评测集格式、配置、依赖、并发与安全均不变。唯一可观察的变化是智能体被调用的次数减少。每轮运行前仍会重新生成会话 ID。没有文档页面描述这一调用模式。

对组件规格无影响：`specs/` 中没有评测组件，本变更既不改变接口也不改变状态，只改变一个已有调用的重复次数。不为单个缺陷修复新建规格。

## 风险与评审

使用带随机性的模型时，每个用例现在使用同一批 `C x R` 次运行的结果，而不是 `C` 次重复遍历的结果，因此分布不变，只是多余且被丢弃的运行消失了。循环中没有任何逻辑依赖这些多余的运行。未发现也不预期有调用方依赖额外运行来做限流预热。

设计已直接评审：范围、兼容性、测试与双语一致性均无未解决的阻塞项。用户批准：2026-10-27 请求将此修复提交到上游。
