# 为 MPA 隐藏不兼容的会话产物入口

## 背景、范围与需求

Composer 对所有已连接 Runtime 会话挂载 `RuntimeArtifacts`，其 hook 在抽屉关闭
时也请求数据。该服务读取 Studio 的 `artifacts/` 或 Runtime 的 `/mnt/artifacts`
挂载，不读取 MPA Worker 的 `/data/output`。用户明确要求支持前先隐藏 MPA 入口。

- `FR-1`：给定现有 Runtime 元数据识别的原生或 A2A MPA 连接，不挂载产物入口/
  组件，也不运行其请求 hook。
- `FR-2`：给定有会话的普通 Runtime，保留既有入口；本地 app、无会话及独立
  Sandbox 页面保留原有条件。
- `FR-3`：普通与 MPA 连接之间切换时重新判断显示。既有 Markdown 文件下载、
  后端鉴权、存储路径、凭据及 MPA 身份/传输分类不变。

## 设计与审查

只在 Composer 挂载条件中增加现有产品判断 `isMpaRuntimeApp` 和
`isMpaA2aRuntimeApp`。不改变具有传输语义的判断函数，不通过 CSS 隐藏，不增加
配置开关，不从镜像/名称推断类别，不接入新存储适配。移除组件沿用其既有取消/
卸载行为。无 schema、持久化或权限变化；隐藏 UI 不作为鉴权控制。
不修改样式、字体、图标、布局，也不添加替代提示。

直接审查（`review-spec` 不可用）检查原生/A2A 覆盖、范围、安全、可测试性及
双语一致性。用户请求批准该范围。Ponytail 选择复用判断；frontend-design 保留
现有视觉体系。引用的 `ui-ux-pro-max` 文件不存在，改按 Studio/Foundation 规范
执行。无设计阻塞项。

真实条件，包括两种元数据及缺 Runtime/会话/Sandbox 边界。默认 npm test 不包含
产物交互测试，需显式执行。构建匹配的 `veadk/webui` 产物，在普通/窄屏检查浏览器，
验证普通到 MPA 的切换。结果记录在本文。没有请求云端部署或真实 Agent 执行；
无 Python 行为变化，无需重跑无关的全量 Python 测试。

### 结果与剩余浏览器检查

生产代码仅修改一行条件，复用两个既有判断。使用实际分类函数执行源码提取的
真实条件，V8 覆盖率 100%（5/5 范围，次数 23/19/15/11/9），不是整个 App 的覆盖率。
TypeScript、Vite 及 widget 构建通过；打包资源验证通过，覆盖 113 个文件和
350 个内部引用。同步更新依赖 hash 的生成 bundle。构建体积告警不阻塞。
diff 空白检查及 pre-commit 通过。

当前源码通过本地 Vite 5188 端口复用已有 8765 后端，未修改该后端或云资源。
浏览器登录、首页及智能体选择器正常呈现；选中 MPA 类型后列表停留加载状态，
无法打开已有会话。真实会话显示、浏览器切换及窄屏检查尚未验证，不将源码矩阵
测试当作浏览器 E2E。未部署云端、未调用模型；不会为剩余检查扩展修复无关问题。

风险：连接元数据缺失时不能识别 MPA，遵循既有分类契约，不猜测。未来 Sandbox
产物支持需要独立适配，本次不实现或承诺该能力。
