# Cloud Studio MPA credentials and OpenViking permissions

[中文版](2026-10-15-cloud-iam.zh.md)

- Date: 2026-10-15
- Status: approved for implementation
- Scope: BytePlus cloud Studio credentials and shared Studio OpenViking policy.

## Background and evidence

`studio deploy` clears deployment secrets before constructing the VeFaaS function environment. Managed BytePlus creation requires either BytePlus AK/SK or an explicit credential file. The deployment currently supplies neither. The shared frontend role grants VikingDB read-only access and selected operations, but does not explicitly grant the three OpenViking provisioning operations. Local AK/SK success does not exercise this role.

## Goals, non-goals and scenarios

New BytePlus cloud deployments must use the mounted rotating IAM credential file for MPA creation. Both cloud providers must grant the default Studio role the operations needed to create an OV library, read readiness and retrieve its user key. Local AK/SK and explicit CLI credential selection remain unchanged. No UI, service activation, quota, model configuration, runtime image, deletion or cloud resource changes are included. Existing installations require redeployment; this change does not migrate live functions or custom roles automatically.

## Requirements and design

- R1: In the BytePlus branch of the allowlisted deployed environment, set `VEADK_MPA_BYTEPLUS_CREDENTIAL_FILE=/var/run/secrets/iam/credential`. Do not copy a developer machine's path or AK/SK. Domestic deployment remains unchanged.
- R2: Reuse existing profile and credential loading: explicit file takes priority and is reread per call; missing, malformed or incomplete files fail without leaking credentials. Keep standalone BytePlus's explicit-file requirement to avoid accidental cross-provider credential fallback.
- R3: Add only `vikingdb:CreateOpenVikingCollection`, `vikingdb:GetOpenVikingCollection`, and `vikingdb:AccessOpenVikingApiKey` to the existing shared custom policy. Reuse existing policy creation/update/readback verification; no deletion permission or broad write wildcard.
- R4: Document redeployment and the distinction between deployer identity and function role. Service activation, quotas and model access remain prerequisites.

Affected implementation: `veadk/cli/cli_frontend.py` and `veadk/cli/frontend_deploy_policy.py`. Tests: `tests/cli/test_studio_deploy_target.py`, `tests/cli/test_frontend_deploy_iam.py`, `tests/integrations/mpa_managed/test_byteplus.py`. Update the paired [component contract](../../../specs/studio-mpa-creation/README.md) and managed module READMEs. Credential selection and permission contracts are affected; HTTP, task state and data contracts are unchanged.
