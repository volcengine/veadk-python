# 云端 Studio MPA 凭据与 OpenViking 权限

[English](2026-10-15-cloud-iam.md)

- 日期：2026-10-15
- 状态：已批准实施
- 范围：BytePlus 云端 Studio 凭据及共享 Studio OpenViking 策略。

## 背景与证据

`studio deploy` 在构造 VeFaaS 函数环境前清除部署密钥。托管 BytePlus 创建要求 BytePlus AK/SK 或显式凭据文件，但部署目前没有提供这两种来源。共享前端角色具有 VikingDB 只读权限及部分操作，没有明确授权三个 OpenViking 准备操作。本地 AK/SK 创建成功并未验证该角色。

## 目标、非目标与场景

新部署的 BytePlus 云端 Studio 应使用挂载的轮转 IAM 凭据文件创建 MPA。两个云平台的默认 Studio 角色均应具备创建 OV 库、查询就绪状态及获取用户 Key 的权限。本地 AK/SK 和显式 CLI 凭据选择不变。不涉及 UI、服务开通、配额、模型配置、Runtime 镜像、删除或云资源变更。已有部署需要重新部署；本改动不会自动迁移线上函数或自定义角色。

## 需求与设计

- R1：在部署环境白名单的 BytePlus 分支写入 `VEADK_MPA_BYTEPLUS_CREDENTIAL_FILE=/var/run/secrets/iam/credential`。不复制开发机路径或 AK/SK。国内部署不变。
- R2：复用现有 profile 和凭据读取：显式文件优先，每次调用重新读取；文件缺失、格式错误或字段不完整时明确失败且不泄露凭据。保留独立 BytePlus 调用要求显式文件的规则，避免意外跨平台回退。
- R3：在现有共享自定义策略中仅增加 `vikingdb:CreateOpenVikingCollection`、`vikingdb:GetOpenVikingCollection`、`vikingdb:AccessOpenVikingApiKey`。复用策略创建、更新及读回校验；不新增删除权限或宽泛写权限通配符。
- R4：说明重新部署要求及部署者身份与函数角色的区别。服务开通、配额及模型访问仍为前置条件。

涉及实现：`veadk/cli/cli_frontend.py`、`veadk/cli/frontend_deploy_policy.py`。测试：`tests/cli/test_studio_deploy_target.py`、`tests/cli/test_frontend_deploy_iam.py`、`tests/integrations/mpa_managed/test_byteplus.py`。同步双语[组件契约](../../../specs/studio-mpa-creation/README.zh.md)及 managed 模块 README。影响凭据选择与权限契约；HTTP、任务状态及数据契约不变。
