# 按来源归一化 MPA 推理快照
[English](2026-09-22-mpa-reasoning-snapshots.md)

## 证据与范围
只读检查本次任务，确认外层状态增量后带有多个 part 的完整消息，沙箱增量后带有完全一致的完整副本。沙箱 tool.call 比最后几个推理字符更早到达。先重放外层历史，再重放沙箱 artifact，可复现重复：现有跨来源后缀比较丢弃了标点，破坏沙箱累积文本。延续用户已批准的推理丢失/重复修正，不重新设计命令展示。

## 需求与设计
FR-1：只归一化显式 MPA A2A 流。解码器新增可选 `mpa_a2a=False`，服务端传入已有的可信 runtime 分类。默认/通用行为保持不变。
FR-2：先合并 MPA 状态消息中相邻的推理 part，再把完整快照与累积外层文本比较；继续支持用量标记的快照。不得跨沙箱/外层或不同调用比较推理。保留真实重复增量和新内容；仅匹配/扩展的完整快照替换已经输出的内容。
FR-3：按任务/调用跟踪沙箱推理阶段。工具结果和答案增量标记下一个推理阶段，但 tool.call 本身不标记：已发出的推理尾部可能比调用晚到。推理附带 `reasoningSegmentId`；限定模式的前端投影将迟到尾部追加到工具行前匹配的 thinking 块。不移动/删除工具行或不同推理阶段。仅多次增量之后与完整累积文本匹配的快照被去重；新阶段即使文本相同也保留。
FR-4：保留失败/取消输出、事件重放去重、最终答案去重、用量及调用隔离。不涉及凭据、云部署、用户状态修改或新依赖。无法重建服务端历史中缺失的事件。

## 任务与验收
T-1/AC-1：先增加失败的模拟回归，覆盖外层多 part 快照、混合来源标点、沙箱完整副本、迟到推理尾部、调用隔离、重复增量和后续不同阶段。
T-2/AC-2：实施后端显式模式、传入 runtime 分类，并增加前端限定范围的阶段投影。同步更新运行时诊断 CON-10 双语契约。
T-3/AC-3：运行定向 Python/前端及代理测试、Ruff/Pyright、完整前端测试/构建/资源检查、隔离浏览器回放、密钥扫描及差异检查。单独记录实际激活；不自动重启仍持有内存会话索引的服务。

## 审查与风险
review-spec 不可用，以直接审查替代。检查需求、安全、状态归属、取消、兼容性及双语等价，无设计阻塞。用户“看看怎么修”延续之前明确修复授权。无显式标记的完整副本识别采取保守方式，仅限包含多个增量的阶段；不同阶段文本相同不能单独作为去重依据。以推理增量之间穿插 tool.call 覆盖异步顺序。不修改 API 请求结构；输出元数据为追加字段。
