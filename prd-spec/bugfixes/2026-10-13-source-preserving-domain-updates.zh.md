# Studio 更新 Skill/MCP 时保留领域应用

状态：已实现。创建：2026-10-13。验证：2026-10-14。
[English](2026-10-13-source-preserving-domain-updates.md)

## 背景与范围

现有数据库领域应用提供 Studio 自省接口，但自行管理工具工厂、动态核心提示词和
启动入口。主线 `a7569a04` 已支持保留源码更新，但生成的 MCP 替换逻辑忽略了应用
兼容处理器。历史 `812faadf` 回归在包装保留、处理器失败和非法处理器三项上失败。
其他缺口涉及延迟加载 ADK、不可变覆盖文件权限、应用身份、连续编辑和前端 MPA 生命周期。

用户要求通过最小完整改造，让 Studio 更新现有 V4 数据库 Skill 和 MCP。保留应用、
Runtime 身份、弹性配置和模型配置。真实验收仅涉及明确授权的 V4 数据库 Runtime；
客户 V4-2 资源不在范围内。

## 需求与设计

真实配置检查发现，通用路由会向原本没有这些字段的领域 Runtime 注入
`MPA_AGENT_ID` 和 `VEADK_STUDIO_ENVIRONMENT_ID`。按已有保留范围，保留源码更新
不得创建 MPA 身份/标签、重置环境选择元数据、继承 Studio 主机配置，或自动解析
替换模型凭证。已有值与普通更新行为须保持不变。生产修改前，在真实 typed-route
回归中增加页面 MPA 分类及主机独有环境标记。已有严格禁用 Sidecar 的过滤合同
独立保持。

1. 通过正式自省接口和准确 OCI digest 恢复已部署配置。保留私有源码和动态提示词，
   不使用 Builder 重新生成应用。
2. 构建包含 Skill 选择与内容、公开 MCP 配置和兼容启动器的小覆盖层。保留入口和
   依赖，不新增 `veadk.aiops` 依赖，不迁移 Managed shared。
3. 尊重应用 MCP 处理器。对受支持的单根 HTTP MCP 应用，生成其既有
   `MCP_SERVERS_JSON` 启动配置，并在接受覆盖层前验证配置完全一致。处理器报错即
   拒绝，不能在失败后用普通工具替换领域包装。
4. 显式激活覆盖层，保留应用导入路径和身份。应用选择依赖后才导入 ADK。
   不可变版本目录必须允许既有非 root 用户读取。
5. 连续更新以最终 Skill 清单为准。只恢复当前覆盖版本，遵守 OCI whiteout 删除
   语义，拒绝不安全的链接和布局。
6. 只输出经过验证的公开 `sourceOverlay` 元数据。元数据缺失、损坏或不匹配时
   阻止编辑，不得切回普通重新生成。令牌在内存解析，仅传给授权控制面，不进入
   构建上下文、浏览器存储、日志或证据。
7. 保留源码编辑允许无法回读的运行时提示词；普通创建校验不变。此模式发布不得调用
   MPA Profile 操作。重新打开编辑后保留已配置的 MCP 凭证引用。

## 发布前发现并修复的配置覆盖

真实发布请求在云写入前被保护检查拦截，暴露两个通用问题：

1. source-preserving 仍沿用普通更新的 Description/APM 写入。按 CON-1，仅对该模式
   省略 `Description`、`ApmplusEnable`，普通更新行为保持。实际路由及 SDK 序列化
   回归：修复前 4 组失败，修复后含普通更新对照的 5 项通过。
2. 通用路由会注入 MPA/环境身份、继承 Studio 主机环境并自动替换模型凭证。
   改为只保留目标 Runtime 原值。实际路由回归：修复前 4 项失败，修复后 5 项通过，
   覆盖凭证缺失/已有、身份保留、主机环境隔离及普通 MPA 更新。

两组回归均进入强制发布门禁；修复后重新运行相关 325 项、后端四阶段门禁和
pre-commit 全部通过；Pyright 保持相同的 38 项基线。配置 dry run 只修改 overlay/MCP
并清理已禁用 Sidecar 的旧字段；Core 在读取旧字段前返回禁用，原禁用开关保留。

第一轮 Update 后，任务验收包装器错误假设待发布版本已递增而拦住 Release。
实际平台语义是 GetRuntime 仍指向已发布版本，GetRuntimeVersion 不传版本返回
VersionNumber=0 的待发布配置。已修复任务包装器并增加机制回归；核对镜像摘要、
待发布环境及保护字段后仅续接一次 Release，没有重复构建或 Update。此问题属于
本地验收包装器，不是产品失败。第二轮随后完整验证了页面发布链路，无需手工续接 Release。

## 镜像仓库读取被拒时的连续 MCP 更新

第二轮真实发布在 Runtime 写入前构建失败。本机直连和已授权 Devbox2 对同一
镜像的请求，均在成功取得令牌后返回 HTTP 401，因此不能归因于本机独有的网络
问题。Studio 回退为保留运行时 Skill 引用；现有构建校验正确阻止丢弃上次已选
覆盖层 Skill，但用户无法完成仅修改 MCP 的连续更新。

在既有 CON-1/CON-3 保留范围内，以固定摘要的源镜像作为独立构建阶段，准备下一
覆盖层。只把上一覆盖层清单中仍被保留的 Skill 复制到新覆盖层，将其名称合入
selected.json，用户明确上传的替换内容保持优先。使用新建临时输出目录，让
非 root 镜像用户也能完成准备；最终阶段以可读权限复制结果，保留源镜像的入口、
用户和依赖。版本目录摘要同时绑定源镜像摘要与输入文件，因为保留内容取决于源镜像。

符号链接、特殊文件、缺少清单/文件、选择不一致及合并后文件数/字节超限均拒绝；
不能删除校验器或静默丢弃 Skill。在实际生成的构建脚本层补充 RED/GREEN 回归，
纳入已有 source-overlay 强制门禁，覆盖保留、替换、移除、连续继承以及非法输入。
随后对同一 V4 完成真实页面发布与数据面验收。不修改仓库权限或其他资源。此方案
落实已授权的连续更新要求，已复核实现边界，不扩展产品范围。

连续构建验证：实际生成脚本修复前复现 4 项失败，修复后 11 项通过；再加入 3 项
原始运行时 Skill/合并限额检查进入强制门禁。相关回归 119 项通过，实际数据库工厂
3 项通过。后端强制门禁：149 通过/1 跳过、覆盖率 96%；lifecycle 9、credentials 233、
release 39 项通过。Ruff、pre-commit 和密钥扫描通过。修改的构建模块 Pyright 为 0，
与之前相同；其他 38 项基线诊断仍存在。真实页面已提交修复后的新 Pipeline Run，
并完成 V19 发布，第二轮数据面验收与再次编辑均通过。

## 交付与验收边界

两轮真实请求均使用原客户主机 IO 告警及历史窗口，通过正式只读 API 取证。第二轮
提示要求最多两次业务查询，实际执行了三次；保留为查询预算遵循上的不足，不声称
模型严格遵守了该预算。更新验收证明保留后的 Skill 执行、所选 MCP 配置、真实业务
回执、完整交付与连续编辑；不代表六个 MCP 的所有业务接口或独立的 SuperAgent/
机器人通道均被验收。

候选 Studio 在本地运行，仅针对明确授权的 Runtime。源码分支和重新生成的前端资源
已具备集成条件；未发布正式 Studio 升级通道版本，也未合入主线。Runtime SDK/Core
继续保持既有部署的锁定版本。
