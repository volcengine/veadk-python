# Studio 工具活动可视化设计文档

- **状态：** 已确认，可进入实施计划
- **日期：** 2026-09-12
- **变更类型：** 功能
- **英文版本：** [2026-09-12-studio-tool-activity-visualization-design.md](2026-09-12-studio-tool-activity-visualization-design.md)
- **目标分支：** `feat/mpa-agent-oneclick-provision`

## 1. 概述

### 1.1 问题

AgentKit Studio 已能接收结构化 ADK 工具调用和 mpa-agent 沙箱进度，但普通工具仍回退为格式化 JSON。一个沙箱命令还可能同时显示外层委托卡和内部 `exec_command`、`commandExecution` 行。用户能看到协议数据，却难以快速判断真正重要的信息：正在做什么、涉及什么命令或资源、已经产生什么输出、是否成功以及耗时多久。

当前实现已有可复用基础：`Block.kind === "tool"`、稳定 `callId` 匹配、`CodexSandboxActivity`、内置工具 registry，以及统一的 `eventsToTurns()` 历史投影。本功能必须扩展这些能力，不另建第二套 transcript 模型。

### 1.2 目标

- 用紧凑的 Codex 风格活动单元替换默认 JSON 优先展示。
- 所有工具共享统一视觉外壳，命令、读取、搜索、文件变更、MCP 和通用工具使用类型化详情。
- 按稳定身份将工具开始、输出、结果和错误合并成一个持续更新的单元。
- 将沙箱内部活动扁平化到对话时间线，同时保留轻量 `Codex Sandbox` 来源标记。
- 运行过程清晰可见、成功结果保持紧凑、失败状态可立即诊断。
- 保证实时投影和持久历史重建产生等价的工具内容与顺序。
- 不影响已有专用卡片、session 历史、搜索、反馈、附件、artifact、A2UI、并行 Agent 和最终回答。

### 1.3 非目标

- 修改 mpa-agent、A2A、ADK 事件协议或数据库 schema。
- 将展开状态等纯展示状态写入 session。
- 替换 `create_agents`、`branch_compare` 等已有专用 renderer。
- 实现不受限制的 JSON 查看器，或暴露已被后端脱敏移除的值。
- 在上游模型只返回最终结果时人为切片伪造流式输出。
- 重做对话页、导航或 Studio 全局视觉语言。

## 2. 用户场景

### 场景 1：查看运行中的命令

**Given** 工具启动沙箱命令并持续输出，
**When** Studio 收到开始和输出事件，
**Then** 同一个展开的活动单元原位更新命令、耗时和最近输出，而不是不断新增 JSON 行。

### 场景 2：查看已完成历史

**Given** session 中持久化了 function call、response 或 Codex activity snapshot，
**When** 用户刷新 Studio 或重新切回该 session，
**Then** 系统重建相同顺序和内容的结构化活动单元，不产生重复调用，也不丢最终回答。

### 场景 3：诊断失败

**Given** 命令或工具执行失败，
**When** 收到终态事件或恢复历史，
**Then** 活动保持展开，并显示简明错误、状态或退出码、已产生的输出，以及二级原始数据入口。

### 场景 4：阅读工具密集型对话

**Given** Agent 连续执行多个相邻且成功的只读操作，
**When** 这些操作完成，
**Then** Studio 可将其收纳为一个“已探索 N 项”分组，同时保留每个子操作及其原始数据。

## 3. 功能需求

### FR-1 — 统一活动外壳

所有普通工具活动使用相同的头部结构：图标、明确状态标记、本地化动作标题、单行摘要、紧凑指标和展开入口。颜色只能辅助表达，必须同时提供文字或图标语义。

### FR-2 — 展示模型

工具展示必须经过纯函数 presentation 层派生。源 `Block` 保留原始 `args` 和 `response`；React 组件不得临时猜测任意 JSON 结构。展示模型包含类别、标题、摘要、状态、来源、耗时、退出码、类型化详情和原始值。

### FR-3 — 生命周期关联

相同稳定 `callId` 的开始、输出、结果和错误必须更新同一个活动单元。重复 `eventId` 必须忽略。结果先于调用到达时，在可安全关联时暂存；无法关联时显示独立的异常通用活动，不得静默丢弃。

### FR-4 — 自适应展开

- 排队中或运行中默认展开。
- 成功后默认折叠。
- 失败后默认保持展开。
- 用户手动展开或收起后，后续事件不得覆盖用户选择。
- 历史恢复按最终状态初始化，不持久化临时展开状态。

### FR-5 — 类型化详情

首期 presenter 包括：

| 类型 | 头部摘要 | 展开内容 |
| --- | --- | --- |
| 命令执行 | 归一化后的命令 | 命令、工作目录、stdout/stderr、退出码、耗时 |
| 读取/列举 | 文件或资源数量 | 路径、行号或范围、省略提示 |
| 搜索 | 查询词和结果数量 | 命中路径或条目及摘要 |
| 文件变更 | 文件数量和 diff 统计 | 路径、增加/修改/删除动作、diff 摘要 |
| MCP | `server/tool` 和结果数量或状态 | 关键输入和结构化结果 |
| 授权 | 请求授权的工具或资源 | 授权说明与主操作按钮 |
| 通用 | 工具名称和尽力提取的摘要 | 可读键值信息 |

授权继续使用现有专用交互，不降级为被动折叠行。已有专用工具 renderer 继续作为权威展示。

### FR-6 — Codex Sandbox 扁平化

`CodexSandboxActivity.items` 中的内部活动作为当前 assistant turn 的一级活动单元呈现。存在结构化子活动时，不再渲染第二层 `delegate_to_codex_sandbox` 大容器；使用轻量来源标记说明连续活动来自 `Codex Sandbox`。最终回答保持在活动分组之外。

### FR-7 — 安全只读聚合

同一 invocation、同一来源中，相邻且已成功完成的读取、列举、搜索或资源查询可聚合为“已探索 N 项”。只在完成后聚合。命令、写入、删除、MCP、授权、失败、取消、来源变化、invocation 变化和最终回答都会结束聚合。聚合只改变展示，不改变原始子项和顺序。

### FR-8 — 原始数据二级入口

每个活动的展开详情底部提供“查看原始数据”。输入和结果分区、延迟格式化、限制渲染规模，并支持分别复制输入、结果和调用 ID。默认关闭，且不得暴露上游 allowlist 或脱敏逻辑已经移除的数据。

### FR-9 — 输出处理

命令实时输出必须原位更新；完成后若存在权威聚合输出则替换预览。默认预览展示受限的头部和尾部，中间明确显示“省略 N 行”。完整输出使用有高度上限的独立滚动区。ANSI 或控制字符必须清理或安全渲染，禁止直接注入 HTML。

### FR-10 — 历史兼容

`eventsToTurns()` 保持为历史重建唯一入口。实时与持久事件使用同一归一化和展示函数。继续兼容 camelCase 与 snake_case。状态、耗时、来源或 call ID 缺失时使用安全降级。无法识别的旧工具仍显示通用活动。

### FR-11 — 响应式与无障碍

窄屏优先隐藏次要摘要，不隐藏标题或状态；详情铺满可用宽度，页面不得产生横向滚动。工具头部和二级折叠支持键盘、`aria-expanded`、清晰焦点和至少 44px 有效点击区。动效仅使用 120–180ms 的透明度或位移过渡，并响应 `prefers-reduced-motion`。

### FR-12 — 国际化

所有动作、状态、省略、复制、空态和错误文案进入现有 `conversation` namespace，并同时提供中英文。只有在具有明确技术价值或进入原始数据时才展示原始工具名。

## 4. 方案设计

### 4.1 数据流

```text
ADK / A2A event
  -> 现有 applyEvent/eventsToTurns 投影
  -> 按 callId 关联工具生命周期
  -> 纯 ToolPresentation 派生
  -> 可选的只读展示聚合
  -> ToolActivityCard + 类型化详情 presenter
```

不改变传输和持久化契约。源 Block 继续保留，供调试和旧数据兼容使用。

### 4.2 建议模块

- `frontend/src/ui/tool-activity/model.ts`：展示类型、安全字段读取、归一化、摘要、输出截断和聚合判断。
- `frontend/src/ui/tool-activity/ToolActivityCard.tsx`：统一头部、自适应折叠、复制操作、原始数据入口和无障碍语义。
- `frontend/src/ui/tool-activity/ToolActivityDetails.tsx`：命令、读取、搜索、文件、MCP 和通用详情。
- `frontend/src/ui/tool-activity/tool-activity.css`：使用现有语义 token 的局部布局与状态样式。
- `frontend/src/blocks.ts`：最小化接入生命周期关联和沙箱扁平化，不放 JSX。
- `frontend/src/ui/Blocks.tsx`：将普通工具交给新 presenter，同时保留已注册的专用 renderer。
- `frontend/src/i18n/resources/{zh-CN,en-US}/conversation.json`：活动文案。

若模块内容很小，实施时可合并文件；但解析、状态归并和 React 展示必须能独立测试。

### 4.3 视觉规范

- 活动行沿用现有 32px 工具头部和 transcript 水平锚点。
- 有效交互高度至少 44px，不要求视觉行本身变得厚重。
- 状态使用中性灰、琥珀、绿色和 destructive 语义色，并同时显示明确文字。
- 命令和输出使用现有等宽字体；标题、指标、ID 和普通摘要使用系统 UI 字体。
- 成功折叠行保持轻边框或无边框；展开详情只使用一条轻量左侧引导线，不嵌套多层卡片边框。
- 运行中更新预留指标区域，避免布局跳动。
- 长标题省略并提供可访问的完整值；输出在自身边界内换行或滚动。

### 4.4 状态归属

工具生命周期数据归 transcript 投影管理；展开状态归每个渲染实例管理；只读聚合是相邻 Block 上的纯展示视图。任何展示状态都不写入 ADK session state 或服务端存储。

## 5. 历史安全契约

历史功能是 P0 发布门禁，必须全部满足：

1. 刷新已完成 session 后，工具顺序、状态、详情和最终回答保持一致。
2. session 切换不得共享展开状态或活动状态。
3. 仅有持久化 `functionCall + functionResponse` 时也能重建完整活动，无需依赖实时 progress。
4. 持久化 Codex snapshot 与实时 progress 不得生成重复子活动。
5. 缺字段或旧版事件必须降级成通用活动，不得抛错或隐藏。
6. 展示聚合不得修改源 blocks，也不得跨 invocation 或最终回答边界。
7. 现有历史列表、搜索、反馈、附件、artifact、A2UI 和并行 Agent 行为保持不变。

如果某类事件无法保证实时和历史等价，首期必须保留该类型现有的通用 renderer，不得上线不完整的专用展示。

## 6. 边界情况

| 场景 | 处理方式 |
| --- | --- |
| 重复开始、输出或结果 | 按稳定事件身份去重，并更新同一个单元。 |
| 结果先于开始到达 | 按 call ID 暂存；无法关联时显示可见的未匹配结果。 |
| 缺少 call ID | 尽可能生成投影范围内的确定性身份；存在歧义时不合并。 |
| 同名工具并发执行 | 只按 call ID 关联，禁止仅按工具名合并。 |
| 超长或疑似二进制输出 | 限制预览、保留省略信息；可安全转成文本时才提供完整视图。 |
| 响应结构异常 | 显示“无法识别的工具结果”和原始数据入口。 |
| 运行中连接断开 | 保留已收到状态；刷新后从历史重建终态，不重新提交任务。 |
| 用户手动收起运行项 | 后续更新保持用户选择。 |
| 专用 renderer 异常 | 隔离到该活动并回退通用 presenter，不使整个 transcript 崩溃。 |
| 字段可能包含密钥 | 延续服务端脱敏，并在展示和复制前使用现有基于值的敏感信息遮罩。 |

## 7. 测试与验收

### 7.1 单元测试

- 命令、读取/列举、搜索、文件变更、MCP、授权和通用 presenter 映射。
- 开始/输出/结果/错误生命周期、重复事件、乱序事件和同名并发调用。
- 头尾截断、省略行数、异常值和敏感字段遮罩。
- 安全聚合边界与子项顺序保持。
- 自适应展开状态及用户手动选择锁定。

### 7.2 历史回归测试

- 断言实时事件投影与 `eventsToTurns()` 历史重放得到等价的归一化活动内容。
- 刷新包含旧 camelCase/snake_case 工具、缺失字段、Codex snapshot、附件、artifact、A2UI 和最终文本的 session。
- 在两个 session 间反复切换，验证无状态泄漏和数据修改。
- 现有历史、搜索、反馈、并行 Agent 和 Codex sandbox 测试必须原样通过。

### 7.3 组件与无障碍测试

- 运行、成功、失败、空结果、异常结果和长输出快照。
- 键盘操作、焦点可见性、`aria-expanded`、可访问状态文案和复制反馈。
- 验证 375px、768px、1024px、1440px，明暗主题和 reduced-motion。
- 流式更新期间无页面横向滚动和布局跳动。

### 7.4 真实 E2E

使用现有 mpa-agent 测试 Runtime：

1. 执行带延时输出的命令，验证一个活动原位更新。
2. 验证成功后折叠，最终回答保持独立。
3. 执行失败命令，验证错误保持展开。
4. 刷新两个 session，对比实时与历史内容和顺序。
5. 并发运行两个 session，验证活动不串流。
6. 验证旧版非流式 Runtime 历史仍可展示。
7. 扫描原始数据视图及复制内容，确保无已配置密钥。

### 7.5 验收标准

- `AC-1`：所有已支持工具的主界面不展示原始 JSON。
- `AC-2`：一个逻辑命令只生成一个持续更新的活动单元。
- `AC-3`：运行自动展开、成功自动折叠、失败保持展开，并尊重用户手动选择。
- `AC-4`：命令输出、退出状态、耗时和省略行数清楚可读且有界。
- `AC-5`：只读工具只在已定义安全边界内聚合。
- `AC-6`：原始输入、结果和 call ID 可通过二级折叠查看和复制。
- `AC-7`：刷新后得到等价的结构化内容，并保留最终回答。
- `AC-8`：已有专用卡片和非工具 transcript 内容无回归。
- `AC-9`：键盘、焦点、读屏、窄屏、主题和 reduced-motion 验证通过。
- `AC-10`：不得显示或复制凭证及未受限制的环境数据。

## 9. 风险与缓解

- **历史回归：** 以实时/重放等价作为发布门禁，并保留通用 fallback。
- **错误关联：** 优先使用 call ID；并发调用存在歧义时禁止按名称合并。
- **渲染开销：** 使用纯函数派生、限制输出，并延迟格式化原始 JSON。
- **视觉噪音：** 成功项折叠，只读活动安全聚合；失败和运行项保持可见。
- **调试信息丢失：** 源 Block 保留原始值，通过二级折叠提供访问。
- **敏感信息泄漏：** 保留后端 allowlist，并在展示和复制前增加基于值的遮罩。
