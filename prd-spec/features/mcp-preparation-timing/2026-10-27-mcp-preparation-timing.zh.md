## 证据、目标与边界

普通 MCP 调用与接收端逐次请求关联已通过隔离验收，但 `TrustedMcpToolset.get_tools` 与 `TrustedMcpSessionManager.create_session` 尚无独立准备计时。工具总耗时不能说明获取工具清单或会话花了多久。

通过已有 Provider 增加两个 INTERNAL Span：`mcp.tools.prepare` 覆盖公开工具准备调用，包括原生请求头构建、缓存、清单查询和筛选；`mcp.session.acquire` 覆盖既有会话获取，包括复用检查、锁等待及必要的首次连接初始化。后者可能位于前者或工具调用内部；这些边界互相嵌套，耗时不能相加，也不推断纯网络或接收端内部耗时。

不新增鉴权、地址、权限、Exporter／Provider 默认值、会话池、重试、超时行为或依赖升级；不验收厂商鉴权、VeIdentity 动态凭据或 Sandbox 分段。不新增调用请求头、URL、工具名称／参数／结果或异常消息等遥测属性。

## 需求与设计

- `FR-1`：`get_tools` 仅在委托原生实现外包一层计时；返回原工具列表，保留原异常与取消。缓存和重试仍由原生逻辑负责。
- `FR-2`：观测 `create_session`，不复制父类池元数据或改变锁归属。将现有分派逻辑提取为私有实现；每次包装调用只执行一次。
- `FR-3`：独立的小型 MCP 辅助模块只记录固定阶段／传输类别和耗时；失败仅记录 `error.type` 及 ERROR 状态，不记录异常消息或事件。父关系来自现有 OTel 上下文，await、取消、并发后均恢复上下文。
- `FR-4`：遥测初始化、属性和收尾失败不能阻止或重执行业务。保护 start／attach／end，并保留原始 BaseException 对象。
- `FR-5`：在已有授权隔离 Runtime 中核验真实准备。客户端若位于夹具内，地址固定为本进程 MCP 服务的 loopback，不提供任意 URL／请求头输入，仅调用合成工具并关闭会话。只将已测试的 MCP 源码补丁加入已验收镜像，保持依赖、SDK 和 29 项 Runtime 字段不变。本设计不授权新建资源、角色或凭据。

## 任务与验收

1. `T-1`／`AC-1`：先补失败离线回归，覆盖成功、原始异常、取消、并发、会话复用与嵌套父上下文；不新增池或重复调用。
2. `T-2`／`AC-2`：实现辅助模块及两处窄适配。注入追踪初始化／attach／属性／end 失败，业务结果、异常和调用次数不变；合成敏感标记不进入新增 Span 属性或事件。
3. `T-3`／`AC-3`：完成 MCP／厂商模式／重试／身份针对回归及仓库要求的完整 Python／pre-commit 检查。同步双语组件契约、设计结果及受影响的使用文档。
4. `T-4`／`AC-4`：在现有隔离接收端执行真实 HTTP 准备与调用，核对模块／依赖身份及 APMPlus 阶段、Trace、父级和耗时。保留先前失败证据；本地 Span 不能替代部署与入库验收。
