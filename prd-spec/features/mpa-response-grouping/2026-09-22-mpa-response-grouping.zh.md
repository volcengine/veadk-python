# MPA A2A 回复区域合并

[English](2026-09-22-mpa-response-grouping.md)

## 范围与证据
ID：`mpa-response-grouping`；日期：2026-09-22；状态：implemented。
契约：[runtime diagnostics CON-11](../../../specs/studio-runtime-diagnostics/README.zh.md)。
当前每个投影助手片段都有独立底栏，所以外层推理和 sandbox 最终答案分别带操作栏。TraceDrawer 已按结束时间查询会话轨迹。用户批准统一回复区域与底栏，并保持通用智能体行为。

## 需求与场景
- FR-1：仅明确识别的 MPA A2A 应用合并用户/系统消息边界之间的相邻助手片段。原始事件/turn 不变。通用 ADK/A2A、原生 MPA 和并行智能体布局保持默认行为。
- FR-2：同一区域保留有序的推理、工具、文本、附件、错误、鉴权卡片；首片段稳定 key 避免流式重挂载。本轮展示或鉴权未完成时隐藏唯一底栏。取消/失败保留已有内容及既有错误处理；下一条用户请求独立。
- FR-3：复制/分享覆盖合并后的答案/区域；反馈与批注保留最后一个答案片段的事件身份。统一轨迹使用所有片段最新可用时间，保留各阶段的会话 span；不新增按请求查询的轨迹接口。
- FR-4：按来源/事件身份记录一次 A2A 用量增量，合并本轮账本而不是累加片段上重复的统计快照。包含仅元数据和末尾用量。缺事件身份时，用来源/请求/调用与用量值作保守回放键。旧 turn 没有账本时按 invocation（或一个无法识别的来源）取已报告最大 token，不虚构缺失 worker 用量。不承诺账单级精度或重建缺失历史。

## 设计与边界
在 `transcriptRows.ts` 用纯展示函数派生合并 turn。App 渲染与批注使用此视图，持久化/流式更新仍使用原 turn。仅 MPA projector 在可选 TurnMeta 字段保存用量账本；晚到用量更新最近片段且不改变完成状态。复用 Blocks、操作栏、轨迹抽屉和样式，不新增依赖、接口/鉴权/后端/云变更。SPEC 引用的前端设计技能在仓库/全局路径未找到，直接遵守既有组件和 SPEC，不重新设计风格。

## 任务与验收
T-1 / AC-1（FR-1,2）：先写失败测试，覆盖合并、稳定身份、用户/系统边界、默认引用不变、运行/结束/取消内容。
T-2 / AC-2（FR-3,4）：先写失败测试，覆盖实时/历史用量、回放、前后置元数据、复制/反馈目标、最新轨迹时间；渲染与批注连接同一派生视图。
T-3 / AC-3：完整前端测试、构建/资源、隔离真实浏览器正常/运行/空/错误/窄屏/键盘检查、双语文档和密钥扫描。无需真实云创建，云模型验证单独报告。

## 评审与授权
用户“改改看”批准此前提出的仅 MPA 合并方案。直接评审（review-spec 不可用）：不改原 turn，不跨请求合并，保留轨迹接口，按来源统计，显式默认禁用，无秘密持久化；双语一致，无阻塞。风险：缺用量身份时无法区分数值相同且无标签的调用；不重建缺失历史。本设计不授权提交/推送/重启。
