## Transaction coordinator ownership

| Atomic boundary | Coordinator owner | Participating stores and lock order | Crash/outside-system boundary |
| --- | --- | --- | --- |
| Profile apply success | `S1-03` ProfileApplyService | `runtime_operations` row, then current `mpa_agents` row; insert applied revision, flip current, finish operation | Studio resource validation occurs before transaction; retry by operation key |
| execution-config PATCH | `S2-03` ExecutionConfigService | lock `session_meta`, compare ETag, insert config revision, update pointer | Remote resource resolve before transaction; digest recheck before dispatch |
| Profile-revision upgrade | `S2-05` upgrade use case | operation row, `session_meta`, new config revision; pointer and operation result in one commit | Target Profile/resource reads before transaction |
| Run acceptance | `S3-02` TurnAcceptanceService | Session active claim, Turn record, frozen execution-config snapshot, dispatch intent | Model/A2A/Worker only after accepted Turn persistence |
| Participant barrier | `S4-02` ParticipantBarrierService | control task/generation row, then participant rows; aggregate transition last | Worker ACK is input; no external effect inside transaction |
| Continuation acceptance | `S4-04` ContinuationService | operation row, old Turn/control generation, linked Turn, dispatch intent | A2A Task creation after commit through idempotent dispatcher |
| Secret migration | `S5-01` SecretMigrationService | external reference creation first; then migration checkpoint + reference + plaintext clear in one DB transaction | Stable reference key enables retry; failure before DB commit retains plaintext |

Lock order is mandatory across code paths to avoid deadlocks. No Task may describe AgentKit, A2A SDK TaskStore, ADK event persistence, Worker calls, or Secret provider calls as participating in a distributed ACID transaction.
