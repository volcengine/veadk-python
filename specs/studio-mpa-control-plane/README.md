## Responsibility

Own the Studio-to-mpa-agent contract for Ark model discovery, immutable Turn snapshots, whole-Turn lifecycle commands/status, Session resource mounts, typed runtime topology, Studio tool discovery, and role-protected secret copy. mpa-agent is the lifecycle authority; Studio is a client and presentation layer.

## Contracts

- `CON-1`: Account model discovery is server-side, credential-free in browser payloads, compatibility-filtered, cached with freshness, and fails explicitly.
- `CON-2`: An accepted Turn freezes its model and submitted resource payload. Non-terminal Turns never observe later browser-side Session edits. A server-owned Session resource revision is not implemented yet.
- `CON-3`: Lifecycle state is durable and generation-controlled. Studio exposes idempotent pause/resume only. `paused` requires main executor and all active workers at safe points.
- `CON-4`: Pause and resume share the Composer primary button. Resume within five minutes continues the same Turn; an expired or unrecoverable resume requires the user's click and creates an incremental Turn in the same Session. Disconnect and timeout alone never start work.
- `CON-5`: Studio currently stores Session mount selections in browser local storage and submits stable Skill Space IDs and versions with the next Turn. Server-owned revisions, conflict detection, and retained invalid-resource state remain follow-up work.
- `CON-6`: Topology contains only configured/observed nodes and typed edges; absent optional resources are affordances, not active nodes.
- `CON-7`: Agent Card capabilities gate model, lifecycle, mounts, and topology behavior for backward compatibility.
- `CON-8`: Environment list responses never contain secret values. Authorized secret copy is no-store, audited without value, and never rendered or persisted by Studio.
- `CON-9`: Composer uses one footer row for attachment, Agent target, model, usage/status, and one stateful primary button. The button means send, pause, pending, or resume according to authoritative Turn state; responsive layouts cannot overlap.
- `CON-10`: Usage exposes input/output/reasoning/cache/total for current Turn and cumulative Session; replay is monotonic-delta safe.
- `CON-11`: Conversation projection preserves `reasoning` and Agent `thought` as distinct semantic kinds. Stable event identity is preferred; cross-channel text deduplication is limited to exact or cumulative-prefix transport replays within the same task/invocation and kind.
- `CON-11a`: Persisted conversation replay assigns an identity that is unique across the entire Session transcript to every user-delimited assistant segment. A projector-local sequence may be reused only when its prefix contains a monotonically increasing history-segment index; later rounds must never upsert over an earlier assistant turn. After streaming completes, Studio may replace the live transcript with persisted history only when that history contains the exact final assistant event that triggered reconciliation and no newer local assistant turn has started. Browser acceptance must count and inspect `.turn--assistant` nodes in order before and after a delayed persistence refresh and a full-page reload; finding expected text anywhere in the page is not sufficient because the same text can appear in the user prompt or reasoning.
- `CON-11b`: An MPA `sandbox_task` activity must reach a terminal UI state in both live streaming and persisted replay. Runtime persistence can contain a sandbox `invocation.completed` event followed by a wrapper `functionResponse` with `status=completed` and `finalAlreadyEmitted=true`, while the live subscription can expose only the wrapper response after answer deltas. Studio treats that wrapper as a control terminal: when its invocation still has an active projected turn, it marks the existing parent `sandbox_task` block completed, preserves already streamed answer/tool blocks, records the wrapper event as the turn completion fence, and closes streaming. If the persisted `invocation.completed` event already closed the turn, the same wrapper is ignored and must not create a duplicate tool card.
- `CON-12`: Tool activity exposes a tool-specific safe action and subject. Unknown tools expose their concrete name rather than a generic completed label.
- `CON-13`: Sanitized tool inputs/results remain completely retrievable by an explicit copy/download action. Preview rendering is bounded, truncation is disclosed, and all detail paths share the same redaction rules.
- `CON-14`: Turn model selection is searchable and keyboard accessible, and remains disabled while a non-terminal Turn owns an immutable model snapshot.
- `CON-15`: Runtime listing exposes `agentCategory` and accepts `agentCategory=general|mpa` for server-side category filtering before visible pagination. The authoritative and only MPA source is Runtime tag `veadk:agent-type=mpa`; image names and artifact URLs are not category inputs. `agentCategory=mpa` must first query the Volcano Tag service with a positive tag filter to obtain candidate Runtime IDs, then hydrate those records by Runtime ID, so sparse MPA results do not require scanning unrelated Runtime pages.

## State and data

- Studio-visible Turn states: `queued`, `running`, `pausing`, `paused`, `resuming`, `interrupted`, `completed`, `failed`. Internal terminalization states may exist but are not user actions.
- Turn control stores generation, idempotency, desired/observed state, participant acknowledgement, safe point, snapshot revision, and classified failure.
- Session resources currently store browser-local deltas separately from Agent defaults. The submitted Turn payload stores resolved Skill IDs/versions and remains immutable for that Turn.
- The current topology combines Runtime-configured Agent/Sandbox nodes with browser-selected Session resources. Dynamic worker lifecycle nodes and a server-owned session execution configuration version remain follow-up work.

## Failure and security

Invalid model/resource inputs fail before side effects. Transitional control failure is never displayed as paused. Conflicts return authoritative generation/state. Secret values are excluded from normal APIs, DOM, state, storage, logs, telemetry, screenshots, and error details. Clipboard copy is a deliberate authorized disclosure and must be audited.

## Compatibility

Old agents keep one default model and their existing non-MPA stop behavior, hide unsupported pause/resume controls, and render verified data only. Native ArkClaw and non-MPA Studio contracts remain unchanged.

## MPA information rail (implemented 2026-09-18)

- CON-16: The conversation rail is visible only for server-classified MPA Runtimes. AGENTS.md comes from the current Runtime’s authenticated `/api/v1/studio/agent-info` `agentsMd`, with explicit empty, unsupported, denied and failed states. Generic instructions are not a substitute.
- CON-17: Bound skills come from configured Skill Space nodes in the Agent Card and the authorized paginated SkillSpace API in the Runtime region. Temporary Session skill mounting is removed; previously stored temporary selections are not sent to MPA. Refresh/cancellation cannot mix Runtime identities or turn a failed listing into empty success.

Design: [MPA information rail](../../prd-spec/features/mpa-agent-info-rail/2026-09-18-mpa-agent-info-rail.md).

The Runtime proxy handles `GET /web/agent-info/{app}` for a Runtime tagged `veadk:agent-type=mpa`, including native app IDs and `a2a-default`. Its additive `AgentInfo.agentCategory` is `mpa`; generic synthesized A2A responses use `general`. Other existing responses may omit the field, which hides the rail.

`AgentInfo.mpa` contains `agentsMd: string | null`, `agentsMdStatus`, `skillSpacesStatus`, and `skillSpaces: {id: string, region: string}[]`. Status values are `ready`, `unsupported`, `forbidden`, and `error`. A document read has a 10-second network timeout with a 4-second connect timeout; 401/403 are forbidden and 404/405/501 unsupported. Studio calls the new read-only metadata endpoint with a dedicated `X-MPA-Studio-Key` from its server-resolved Runtime key. On 404/405 it can try the legacy `/api/v1/agents` JWT route without that dedicated header; authorization failure there means the Runtime needs an upgrade. No API key is substituted for a JWT. Invalid payloads and transport failures are errors. Only document/name/description/model strings are allowed through from the upstream details response. Space discovery remains independent from document read failures.

Space IDs come from configured `skill-space` nodes connected to an `agent` node by a `mounts` edge in `urn:veadk:mpa:resource-topology:v1`. Missing topology is unsupported, not an empty-success binding. Space listings use the existing authorized `/web/skill-spaces/{id}/skills` route, request 100 items per page, and reject no-progress or over-100-page traversal as incomplete errors. Each request retains the existing 30-second client timeout and supports cancellation. Counts are shown only for complete listings; degraded results and partial failures retain readable items with a warning, while denied access clears prior skills. No changes are made to Runtime credentials, bindings, or deployment. Bound skill names open the permission-aware [Skill document editor](../studio-skill-document/README.md).

- `CON-16`: Current scope reuses the existing Studio creation form and AgentKit platform resources, then adds MPA Runtime provisioning, Profile application, session execution configuration, conversation results, and Debug. Managed Agent CRUD/version/Session and MPA template/expert/review-install products are excluded. Scheduled tasks, Feishu, website integration, Resource Library, and Search are deferred. No historical ArkClaw data import.
- `CON-17`: Management backend derives identity from a validated Studio OAuth/gateway bearer and forwards only that validated token to a custom-JWT Runtime; it does not self-issue a new token. CLI authenticates to the same BFF. Never accept browser owner/account headers as authority, expose runtime credentials in the UI, or substitute a cloud service role for user identity. M0 proves issuer/audience/client, JWKS rotation, claim mapping, and revocation before enabling this mode.
- `CON-18`: Replace browser-local MPA execution-config authority with runtime `CON-3` “session execution configuration version.” Preserve unsaved edits only as clearly labelled drafts; GET refreshes authoritative state. PATCH uses strong ETag, handles `428` and `412`, and shows current state plus explicit retry/reapply. Never silently overwrite another client. Turn creation uses the accepted execution-config revision. AgentKit/Studio retains resource bodies; Runtime stores stable references and Turn execution records.
- `CON-19`: UI renders allowed lifecycle actions and observed participant state from runtime `CON-4`. A partial pause/deadline failure is not paused. For `new_turn_required`, explicit continuation calls the runtime-owned idempotent continuation API; it never submits an independent fallback prompt. No disconnect or polling timeout starts work.
- `CON-20`: Studio validates and normalizes the accepted Agent draft into the authoritative MPA Profile revision; Runtime persists immutable executable revisions. Same revision/digest is idempotent; lower revisions or same-revision/different-digest conflict. Existing Sessions pin their creation-time Profile revision and adopt a newer revision from the next Turn only after explicit successful upgrade. Creation shows deploying and cannot report runnable until Runtime, Profile, and execution-ready smoke all pass.
- `CON-20a`: The browser calls only VeADK BFF `/web/mpa/agents`. BFF validates the existing Studio Agent draft and calls the typed mpa-agent Profile API. P0 does not call Managed Agent CRUD/version APIs and does not use server-side arkcli subprocesses. Create/update operations persist through Studio TOS `forbid_overwrite` plus ETag; both write endpoints require a browser-persisted `Idempotency-Key` and return `202 + operationId`. The same principal/operation/target/key/hash returns the same operation. Refresh recovers by operation ID or `GET /web/mpa/agent-operations?status=active`; retry resumes from the last safe stage.
- `CON-20b`: Local Studio development may use a process-local MPA operation repository only when `veadk studio --dev` is active and Studio TOS is not configured. It must preserve the same operation ID, request-hash idempotency, and ETag compare-and-swap semantics needed by the UI, but it is not durable and is not release evidence. Non-dev deployments without Studio TOS keep returning `mpa_operation_service_unavailable` for Profile write routes.
- `CON-21`: Current interactive/Debug execution delegates to runtime services with authorization and isolation. Channel/job management and library-wide artifacts/adapters are deferred; preserve existing behavior.
- `CON-22`: BFF and CLI share the public async `veadk.integrations.mpa.MpaControlPlaneClient` schemas/auth/errors/capability negotiation without CLI importing server routes. The client calls only Studio BFF APIs, never accepts a Runtime Secret, normalizes bearer injection, preserves response ETags, requires caller-stable `Idempotency-Key` for writes and `If-Match` for CAS updates, and maps HTTP/timeout failures into redacted `MpaControlPlaneError` values with `code`, `status_code`, `request_id`, `retryable`, and optional `current_state`. Only bounded machine-readable response codes may populate `code`; free-form response details fall back to `http_<status>` and are not exposed. Lifecycle recovery uses active-list plus owner-scoped `GET /web/mpa/agent-operations/{operationId}` for terminal results and retry uses the original request identity rather than inventing a new key. Normal/loading/empty/error/denied/stale/retry states are distinct; model lock, IME/keyboard and narrow-window rules still apply. Unsupported Runtime capabilities show explicit read-only/unsupported behavior, never insecure fallback.
- `CON-22a`: The existing `veadk mpa create` remains the backward-compatible infrastructure provisioning command. Studio control-plane parity is exposed under the separate `veadk mpa control` group with `view`, `create`, `update`, `operation list|get|retry`, `profile status|apply`, `session config-get|config-patch|profile-upgrade`, and `delete-preview`. The group accepts the Studio BFF base URL and a bearer from explicit options or controlled environment variables, never prints the bearer, and reads Profile/request/change payloads from JSON files or stdin. Mutations require an explicit caller-persisted idempotency key where the BFF contract requires one; CAS commands require an explicit ETag or Runtime revision. Successful results and control-plane errors are JSON; local option/input errors use Click's usage-error text. Exit codes are stable: `0` success, Click's `2` for local usage/input errors, `3` for `401/403`, `4` for `409/412/428`, `5` for retryable transport or server failures, and `1` for other validated control-plane failures. Chat, Turn execution, and Runtime diagnostics remain existing Studio execution/diagnostic surfaces; this CLI does not call Runtime directly or claim parity for a BFF contract that does not exist.

New-platform data/version compatibility remains required; only historical ArkClaw migration is excluded. Tests for `CON-16` through `CON-22` map to PRD `AC-1`, `AC-2`, `AC-4`, `AC-5`, `AC-7`, `AC-8`, `AC-10`, with unit/BFF tests, real browser flows and isolated cloud E2E.
