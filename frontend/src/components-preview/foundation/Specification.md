# 前端开发规范

AI 在规划、开发和检查前端页面、组件、布局与交互时，必须遵循本规范

## 适用范围

火山引擎与 BytePlus 使用同一套要求

**必须、禁止**表示强制要求；**优先**表示默认选择，只有已有能力不能满足需求时才考虑其他实现

用户当前明确要求优先于本规范，本规范优先于通用设计建议与示例写法；用户指定的例外仅适用于指定范围，不能扩展到其他页面或组件

## 文案分隔

**S1 | 禁止使用中点「·」连接界面文字，需要文本分隔符时优先使用竖线「|」**

- 适用于标题、描述、标签、状态、元信息和浏览器标题中的文字拼接
- 竖线两侧保留空格，例如「Agent A | 运行中」
- 已能通过留白、分组或换行表达关系时，不额外插入分隔符

## 复用组件

**S2 | 优先使用组件库中的已有组件，通过公开属性和插槽完成配置**

- 开发前先查看 Base、Block 中的现有实现、属性定义和预览示例，再决定是否新增组件
- 引用组件时，禁止通过大量样式覆盖、深层选择器、内联样式或复制源码，将其改成另一套外观；只有用户明确要求定制时才允许，并限制在指定范围内
- 使用已有的尺寸、变种和主题选项属于正常配置；页面容器负责排布，不应重新定义组件内部的字号、颜色、圆角和动效
- 现有能力不足时，先说明缺口并提出组件级扩展方案，不能在页面里维护一套近似实现

## 复用布局

**S3 | 优先选择已有 Layout，再组合 Block 与 Base 组件**

- 先检查 App Layout、Detail Page、Resource Page、Card Layout、Modal Layout 等已有布局是否适用
- 复用布局的内容区域、插槽、对齐方式、间距、滚动边界和响应式行为，避免重新拼装近似的侧栏、头部与主体结构
- 只有已有布局无法承载需求时才设计新布局，并说明现有布局缺少什么能力

## 保留组件完整行为

**S4 | 复用结果必须与组件原有的外观、属性语义和交互行为一致**

- 阅读完整接口和默认行为，接入当前场景所需的属性、事件回调、引用、插槽与状态，不只复制静态外观
- 保留加载、禁用、错误、选中、展开与收起状态，以及已有动画、滚动、焦点、键盘操作和无障碍语义
- 不必传入所有可选属性，但不得改变其默认含义，也不得遗漏需求需要的能力
- 检查时对照组件库的真实示例，确认尺寸、字号、图标、圆角、状态切换和动效保持一致

## 字体

**S5 | 没有用户明确的特殊说明时，禁止使用代码字体或等宽字体**

- 界面文字继承现有 UI 字体，不为单个页面、字段或组件擅自切换字体
- 不能因为内容是 ID、版本号、模型名、文件路径、命令或日志，就自动把它视为使用代码字体的例外
- 用户明确要求代码字体时，仅在指定内容区域使用，不扩散到标题、标签、按钮或周边说明

## 动效

**S6 | 开发时主动考虑状态变化的过渡，避免内容生硬跳变**

- 对新增内容、名称切换、展开与收起、加载与操作反馈，先检查已有组件是否提供动效，并完整复用
- 需要新增动效时，优先使用已有动效参数和实现方式，让变化的顺序清楚，例如先展开空间再渐显内容、名称向上淡出再滑入下一项
- 加载状态可使用循环运动表达正在执行；静态内容不应为了装饰而持续运动
- 动效不能阻塞操作，应能响应中途的状态变化；尊重减少动态效果偏好，降级后仍能清楚表达状态

## 产品文案

**S7 | 提示词中的设计约束必须落实为产品行为，禁止将其复述为界面说明**

- 标题、描述、按钮、提示、空状态和错误信息只表达用户任务、业务含义、当前状态和可执行的下一步
- 用户提示词中的「显示什么」「不要显示什么」「如何布局」属于开发指令，不是待展示的产品内容；不能把执行这些指令的结果写进标题、简介、表格说明或提示
- 例如，用户要求「不要显示用户头像」时，应直接省略头像，禁止额外写「未显示用户头像」「已隐藏用户头像」；没有必要的产品信息就不添加说明
- 不为解释布局、组件选择、字号或动效的实现方式添加说明，也不把需求原话改写成页面副标题；只有用户明确指定为产品文案的内容才按文案处理
- 每条文案都应回答「用户需要知道什么」或「用户可以做什么」，不能只说明「开发者按什么要求做了什么」

## 视觉与光学对齐

**S8 | 所有元素都必须检查几何对齐和光学对齐，以实际视觉效果为准**

- 先确定共享的左、右、上、下边缘、中心线和文字基线，标题、正文、表单、按钮、图标、分隔线与并列容器都应遵循对应的对齐关系
- 对齐不仅看容器尺寸和坐标，还要检查图形的可见轮廓、视觉重心、内部留白，以及图标与文字的实际搭配；数学居中不等于视觉居中
- 优先通过已有布局、间距规则和组件本身修正偏差，确有光学误差时仅对具体元素做有依据的局部校正，不在页面中堆叠补偿偏移
- 检查不同字号、图标尺寸、文字长度、屏幕宽度和交互状态下的真实渲染，避免默认状态对齐、变化后错位

## 执行与检查

1. 开发前列出可复用的布局、组件及其属性、状态和动效，确认是否存在用户明确指定的例外
2. 实现时先使用公开配置；遇到能力缺口先说明，不用大量页面样式覆盖掩盖问题
3. 完成后逐项检查 S1 至 S8，核对文字分隔、字体、组件完整性、状态过渡、产品文案，以及所有元素的视觉与光学对齐
4. 交付时说明复用了什么、有哪些明确例外、实际检查了哪些状态，不把未验证内容写成已通过
