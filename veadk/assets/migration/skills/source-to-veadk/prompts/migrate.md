# Task

Migrate the uploaded source project into a deployable VeADK + AgentKit Runtime project.

Use environment variables only:

- `AGENTKIT_MIGRATE_INPUT_DIR`: source project, read only.
- `AGENTKIT_MIGRATE_OUTPUT_DIR`: generated project, write only here.
- `AGENTKIT_MIGRATE_STATUS_DIR`: migration status.
- `AGENTKIT_MIGRATE_SKILL_PATH`: skills root.
- `AGENTKIT_MIGRATE_ASSET_DIR`: `source-to-veadk` skill directory.
- `AGENTKIT_MIGRATE_SOURCE_CAPABILITIES`: source capability evidence generated by the CLI runner.
- `AGENTKIT_MIGRATE_CONTEXT_JSON`: concise CLI-generated migration context.
- `AGENTKIT_MIGRATE_CONTEXT_MD`: human-readable CLI-generated migration context.
- `AGENTKIT_TARGET_PROJECT`: target AgentKit project for `.agentkit/agentkit.yaml`.
- `AGENTKIT_TARGET_CLOUD_PROVIDER`: target cloud provider for `.agentkit/agentkit.yaml` (`volcengine` or `byteplus`).
- `AGENTKIT_TARGET_REGION`: target AgentKit region for `.agentkit/agentkit.yaml`.

## Pre-Codex Context

The CLI runner already bootstrapped the AgentKit runtime skeleton and ran deterministic source capability detection before starting Codex. Treat those generated files as context, not as control logic. They guide best-effort migration; they do not replace source inspection or judgment.

## Required Reads Before Editing Generated Files

Before editing generated files, read:

1. `$AGENTKIT_MIGRATE_CONTEXT_MD`
2. `$AGENTKIT_MIGRATE_CONTEXT_JSON`
3. `$AGENTKIT_MIGRATE_SOURCE_CAPABILITIES`
4. `AGENTKIT_MIGRATE_SKILL_PATH/source-to-veadk/SKILL.md`
5. `AGENTKIT_MIGRATE_SKILL_PATH/veadk-agent-development/SKILL.md`
6. The matching source reference:
   - `source-to-veadk/reference/dify.md` for Dify exports.
   - `source-to-veadk/reference/any.md` for arbitrary source projects.
7. `source-to-veadk/reference/adk-skill.md` when context, detector output, or source inspection finds project-owned business skills.
8. `source-to-veadk/reference/agentkit.yaml.template` before finalizing `.agentkit/agentkit.yaml`.
9. `agentkit-cli/SKILL.md` only when writing deploy/invoke instructions or diagnosing CLI behavior.

## Required Execution Loop

1. Analyze the source project deeply. Use static inspection first; run safe local commands only when useful. Treat `$AGENTKIT_MIGRATE_SOURCE_CAPABILITIES` and `$AGENTKIT_MIGRATE_CONTEXT_MD` as evidence generated by the CLI runner. Do not leave source capability evidence in `AGENTKIT_MIGRATE_OUTPUT_DIR`; summarize its result in `migration_metadata.json` and `convert_report.md`.

   Always default AgentKit migration observability on: set `envs.ENABLE_APMPLUS` to `true` in `.agentkit/agentkit.yaml`, set top-level `apmplus: true`, set `ENABLE_APMPLUS=true` in `.env.example`, and set the agent-side `ENABLE_APMPLUS` flag to `true`. This default does not depend on whether the source project already used OTEL/APM, but source observability signals must still be recorded as evidence. If the detector reports guardrail/safety/moderation signals, record the signal. Default `ENABLE_LLM_SHIELD` to `true` only when `TOOL_LLM_SHIELD_APP_ID` and `TOOL_LLM_SHIELD_API_KEY` are intentionally configured; otherwise default it to `false`. Users must still be able to override both switches at deploy/runtime.
2. Dynamically generate `source_behavior_contract.json` from the source evidence. The bootstrap file is only a placeholder schema; replace every `pending_source_analysis` value. This contract is for Codex first and for the user second: read it back, then use it as the single source of truth for implementation, eval cases, and reports. Do not write a generic or hard-coded contract.
3. Write and maintain `migration_plan.md` in the output directory.
4. Replace bootstrap placeholder behavior with source-specific behavior.
5. Preserve safe deterministic source logic as VeADK tools.
6. Preserve docs/prompts/runbooks and source business skills as generated ADK skills, references, or assets when doing so improves behavior preservation. If `$AGENTKIT_MIGRATE_CONTEXT_JSON` lists source skills, read `reference/adk-skill.md` before editing `assistant/agent.py`.
   - If the source contains `SKILL.md` under `.codebuddy/skills`, `skills/`, or another project-owned business-skill directory, copy it to `skills/<skill-name>/` with its `references/`, `assets/`, non-secret `scripts/`, and non-secret `config/` resources.
   - `assistant/agent.py` must load local business skills with `google.adk.skills.load_skill_from_dir` and mount them through `google.adk.tools.skill_toolset.SkillToolset`. Do not only paste skill content into `instruction`.
   - When skill scripts are present, do not expose `run_skill_script` by default unless an explicit `code_executor` boundary is configured. For read-only migrations, filter the toolset to `list_skills`, `load_skill`, and `load_skill_resource`.
   - Source-skill materialization is a best-effort behavior-preservation path, not a license to produce generic output. If a skill cannot be safely materialized, report the limitation explicitly in `migration_metadata.json` and `convert_report.md`.
   - If `skill-creator/scripts/quick_validate.py` is available, use it only as a read-only validator for generated skill directories. Do not run `init_skill.py`, `generate_openai_yaml.py`, or any skill-creator command that rewrites, reinitializes, reformats, or regenerates existing/generated business skills. Fix only minimal generated-copy frontmatter/path/resource issues when validation reports them.
7. Record unsupported external systems with exact configuration requirements.
8. Preserve behavior conservatively:

   - Do not introduce unrelated assistant names, report authors, product names, or personas absent from the source-visible contract.
   - Do not override CLI-provided deployment settings. If `AGENTKIT_MIGRATE_APP_NAME` is set, keep it as the AgentKit app `name:` after bootstrap normalization. Keep `AGENTKIT_TARGET_PROJECT` as `.agentkit/agentkit.yaml` `project:`. Keep `AGENTKIT_TARGET_CLOUD_PROVIDER` as `.agentkit/agentkit.yaml` `cloud_provider:` and `AGENTKIT_TARGET_REGION` as `.agentkit/agentkit.yaml` `region:`. Put source/project identity in the agent `name`, description, and instruction instead. Preserve `AGENTKIT_TARGET_MODEL_ID`, `AGENTKIT_TARGET_MODEL_BASE_URL`, and `AGENTKIT_TARGET_MODEL_API_KEY_ENV` in generated config, `.env.example`, and agent model defaults. The generated agent must read the same model API key env named by `AGENTKIT_TARGET_MODEL_API_KEY_ENV`; do not introduce an empty `MODEL_AGENT_API_KEY` alias when the target key env is customized. The CLI `AGENTKIT_TARGET_MODEL_BASE_URL` value must be rendered as the canonical VeADK env `MODEL_AGENT_API_BASE`; do not write legacy `MODEL_BASE_URL` into `.agentkit/agentkit.yaml` or `.env.example`.
   - Do not convert relative times such as “昨天/今天/下午 3 点” into invented absolute dates. Carry the relative expression through or ask the user for an exact date.
   - For read-only/no-write source agents, refuse direct code/config/database/service changes. You may provide analysis and recommendations for the user to execute, but do not imply the migrated agent can perform prohibited changes after confirmation.

9. Generate a deploy-time eval suite from `source_behavior_contract.json`:

   - `eval/cases.json`: at least 3 source-specific JSON cases, each with non-empty `input` and `reference_output` only. Do not add `dimension` or other metadata fields to this file; it must be directly importable by `agentkit eval dataset add --file eval/cases.json`.
   - `eval/rubric.md`: AgentKit evaluator rubric for behavior preservation, safety, and honest limitation reporting. It must reference `{{input}}`, `{{output}}`, and `{{reference_output}}`, and require a numeric score (`1`, `0.5`, or `0`) plus one short reason. Do not make PASS/PARTIAL/FAIL the primary output.
   - Cases must collectively exercise the `source_behavior_contract.json.eval_coverage` dimensions `normal_behavior`, `tool_or_capability`, and `unsupported_external_or_safety_boundary`.
   - Cases must be based on the behavior contract, not generic smoke prompts.

10. Preserve observability and safety boundaries:

   - Keep `AgentkitAgentServerApp` as the serving boundary so AgentKit request/session traces, metrics, logs, A2A, and session APIs stay available.
   - Preserve the bootstrap `_build_tracers()` pattern, or an equivalent env-gated VeADK tracer setup, so agent/tool spans can be exported to APMPlus when `ENABLE_APMPLUS=true` and credentials are available through `OBSERVABILITY_OPENTELEMETRY_APMPLUS_API_KEY`, `VOLCENGINE_ACCESS_KEY`/`VOLCENGINE_SECRET_KEY`, or VeFaaS IAM.
   - Missing observability credentials must not break local validation, deploy, or invoke. Because migrated runtimes default APMPlus on, log a warning and skip exporter setup when no APMPlus API key, Volcengine AK/SK, or VeFaaS IAM credential is available.
   - Preserve the bootstrap `_build_safety_callbacks()` pattern, or an equivalent env-gated VeADK LLM Shield callback setup. It must remain manually controlled by `ENABLE_LLM_SHIELD=true|false` and require both `TOOL_LLM_SHIELD_APP_ID` and `TOOL_LLM_SHIELD_API_KEY` before enabling callbacks.
   - Preserve source read/write boundaries and unsupported external-system behavior honestly. Do not fake database, cloud, HTTP, MCP, model, or APM success.

11. Run deterministic post-step validation:

   ```bash
   bash "$AGENTKIT_MIGRATE_ASSET_DIR/scripts/validate_runtime.sh"
   ```

   If it fails, inspect the failure output and `validation_findings.json` when present, fix generated files, and rerun it. Treat fatal findings as blockers. Treat repairable findings as issues to fix best-effort; if a repairable item cannot be safely resolved, document the limitation instead of faking success. Treat degraded findings as non-blocking limitations. Do not call a model during default post-step validation.

## Mandatory Output

The output directory must contain:

```text
assistant/__init__.py
assistant/agent.py
main.py
requirements.txt
Dockerfile
.dockerignore
.agentkit/agentkit.yaml
.env.example
migration_plan.md
source_behavior_contract.json
migration_metadata.json
convert_report.md
eval/cases.json
eval/rubric.md
```

`assistant/agent.py` must export `root_agent`. `main.py` must expose `app` through `AgentkitAgentServerApp`.
`source_behavior_contract.json` must be dynamically generated from the source project. Prefer `schema_version: 1` and include source summary, entrypoints, visible behaviors, typical inputs, output contracts, tools/integrations, state/memory, external dependencies, safety boundaries, unsupported/degraded behaviors, migration mapping, and eval coverage. Use concise strings for simple facts and structured JSON objects when HTTP method/path, CLI command, tool name, credential, or limitation fields make the source contract clearer. `eval_coverage` must be a string array with the required behavior dimensions. The file must not contain `pending_source_analysis`.
`.agentkit/agentkit.yaml` must include top-level `apmplus: true`. Runtime switches such as `ENABLE_APMPLUS` and `ENABLE_LLM_SHIELD` must be under `envs:`, not at the top level.
`.dockerignore` must exclude migration audit/eval/intermediate files from the runtime image: `source_capabilities.json`, `source_behavior_contract.json`, `migration_metadata.json`, `migration_plan.md`, `convert_report.md`, `eval/`, `.codex/`, `.agentkit/migrate/`, `.agentkit/artifacts/`, caches, and Python bytecode.
If `validation_findings.json` exists, include it in `.dockerignore` as a migration audit file.
Do not write empty `OBSERVABILITY_OPENTELEMETRY_APMPLUS_API_KEY`, `OBSERVABILITY_OPENTELEMETRY_APMPLUS_ENDPOINT`, or `OBSERVABILITY_OPENTELEMETRY_APMPLUS_SERVICE_NAME` entries to `.agentkit/agentkit.yaml` or `.env.example`. They are optional overrides and may be added only when intentionally configured.
`.env.example` must include `ENABLE_APMPLUS=true`. Users may override it to `false` at deploy/runtime when they intentionally disable migrated APMPlus tracing.
Do not generate `OTEL_SERVICE_NAME` or `OTEL_RESOURCE_ATTRIBUTES`; they are not part of the migrated runtime contract.
`.env.example` must include `ENABLE_LLM_SHIELD=true|false`. If `TOOL_LLM_SHIELD_APP_ID` and `TOOL_LLM_SHIELD_API_KEY` are missing, default `ENABLE_LLM_SHIELD=false` and do not write empty credential envs. If both credentials are intentionally configured, write them together as required deploy-time env references and include `TOOL_LLM_SHIELD_REGION` when needed.
`migration_metadata.json` and `convert_report.md` must record observability and safety guardrail support, source detection signals, default enabled states, and manual override envs.
Do not leave legacy or compatibility shim root files such as top-level `agentkit.yaml`, `agent.py`, `${AGENTKIT_MIGRATE_APP_NAME}.py`, or `agentkit_migrated.py`; the deployable app is `main.py` + `assistant/agent.py` + `AgentkitAgentServerApp` + `.agentkit/agentkit.yaml`.
Do not leave migration-only intermediate files in the generated project, such as `source_capabilities.json`, `.codex/`, `.agentkit/migrate/`, `.agentkit/artifacts/`, `__pycache__/`, or `.pytest_cache/`.

## Boundaries

- Do not modify the input project.
- Do not install source-project business dependencies in the migration sandbox.
- The only allowed sandbox bootstrap packages are `veadk-python`, `agentkit-sdk-python`, and their transitive dependencies.
- Do not write plaintext secrets. Use environment-variable references.
- Do not fake database, cloud, APM, HTTP, MCP, or model success.
- Do not call the model during default post-step validation.
- Do not paste large source documents or business skill bodies into the agent instruction. Store them as ADK-compatible skills/references/assets/scripts and mount local skills through `SkillToolset`; instruction should only explain when to use them and what safety boundary applies.
- Do not use `skill-creator` to rewrite or regenerate migrated business skills. It is allowed only for read-only quick validation.
- Escape braces before embedding any source snippet in ADK/VeADK instructions, including env placeholders like `${ENV_VAR_NAME}`; write `${{ENV_VAR_NAME}}` or plain `ENV_VAR_NAME` instead.
